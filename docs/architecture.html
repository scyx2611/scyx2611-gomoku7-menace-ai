一局訓練對弈的資料流

  1. 開局

    trainer 建立 Game，以該局種子重設雙方亂數；AI 執黑先手（可切換為後手）。

  2. AI 看局面

    盤面轉成「自己 / 對手 / 空」的相對表示；開啟去重時取八種對稱中的標準形，得到局面識別碼。

  3. 抽位子牌

    查出每個空位的牌數，依 P(a|s) = w(s,a) / Σw 抽一個位置，轉回實際座標，並記下抽前牌數。

  4. 對手落子

    對手自行決定位置；AI 只「旁觀」，把對手在此局面下的位置寫進對手記憶。

  5. 判定

    rules 判斷五連或棋盤下滿；未結束就回到步驟 2。

  6. 獎懲

    依結果對本局每個 (局面, 位置) 增減牌數，套用下限，記下更新後牌數。

  7. 紀錄

    整局寫入 JSONL（可重播驗證）並更新 CSV 統計；評估模式跳過步驟 6，權重不變。

實驗如何對應老師的要求

修正前 → 修正後
  • 先用預設獎懲跑完整訓練，記錄首次勝利局數與每局棋譜
  • 分析失敗原因後修改，再重新訓練
  • 兩輪數據都保留，不覆蓋
四個檢討問題
  • 先後手：同設定分別以先手、後手訓練
  • 局面去重：對稱開/關，比較局面數與勝率
  • 對手記憶：記錄統計，避讓開/關比較
  • 獎懲效果：不同參數，同一對手、同局數
公平比較
  • 訓練前後用同一對手、同一規則
  • 評估時凍結權重
  • 所有數字都來自實際執行
外部引擎的位置
  • Rapfi 不參與獎懲，不計入「由敗至贏」
  • 只作為最強的評估對手與介面中的對照 AI
  • 報告中把「搜尋/引擎找到好棋」與「獎懲學習」分開陳述
